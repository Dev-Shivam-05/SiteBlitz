# Website Transformation — Refined Prompt Review Guide

**Version:** 1.0  
**Date:** 31 October 2026  
**Language:** Roman Hindi  
**Status:** Prompt draft ready for owner review. Website audit, genuine AI debate, and implementation have not been executed in this chat.

## Aap asal mein kya create karna chahte hain?

Aapki request ko sirf "website ko beautiful banao" kehna galat hoga. Aap ek aisa end-to-end digital sales experience chahte hain jo company ki original identity banaye, premium creative work dikhaye, storytelling ke zariye services samjhaye, mobile par kabhi na toote, interested visitors ko qualified enquiries mein convert kare, aur owner ko reliable admin analytics aur sales operations control de.

Aap "heavy animations" ko sirf eye candy ke roop mein nahi dekhte. Aap chahte hain ki scroll karne ke saath company ki service, value, process, problem-solving approach, aur outcomes naturally samajh aayein. Isliye refined prompt mein motion ka har scene kisi actual business message se linked hai.

## Rulebook ka use kaise hua?

Attached **Universal Prompt Engineering Rules & Structure** ko master standard maana gaya. Iske key requirements directly applied hain:

1. **WHAT:** clear mission, primary objective, owner context, success outcomes.
2. **HOW:** role, source priority, project inputs, ordered workflow, verified debate, decision hierarchy, tools, constraints, creative research.
3. **DONE:** exact deliverables, testing criteria, edge cases, approval gate, completion condition, version control.
4. **XML structure:** primary master file mein 25 named XML sections hain; file ko XML parser se validate kiya gaya hai.
5. **No filler ya fake persona:** exaggerated motivation ki jagah actual standards, technical trade-offs aur testable instructions diye hain.
6. **Evidence and ambiguity control:** project identity unknown ho to infer nahi karna; access na ho to audit complete bolna mana hai.
7. **Iterative improvement:** stages, alternatives, failure tests aur review cycle defined hain.
8. **Static versus dynamic inputs:** system rules main file mein; actual project URLs, repo, services aur debate invocation execution time par discover honge.

## Important feasibility corrections

- Normal website se visitor ka **personal Chrome history** ya future 15-day browsing history lena technically possible nahi hai. Browser extensions alag permission-based products hain, normal website capability nahi. Aapka original business objective — genuinely interested visitor ko identify karna — first-party activity, enquiry context, CRM aur consent-aware intent scoring se partially solve ho sakta hai.
- "100x better than awards websites" ek creative aspiration hai, proven measurement nahi. Refined prompt usko originality, usability, storytelling, speed aur conversion evaluation mein translate karta hai.
- "Maximum data" ko "maximum useful information with minimum necessary personal data" mein convert kiya gaya hai. Yahi trust, form-completion rate aur governance ke liye better design direction hai.
- "Heavy animation" maintain kiya hai, lekin usability, reduced motion, mobile aur Core Web Vitals ko non-negotiable quality gates banaya hai.
- Genuine reviews aur actual past projects bina evidence ke generate nahi karne hain.

## Is chat mein kya verify hua aur kya nahi?

**Verified:** uploaded rulebook padha gaya; revised master prompt file create hui; XML parser se uski well-formedness validate hui; current conversation ke accessible `/mnt/data` folder mein user ki rulebook ke alawa koi pre-existing project prompt, source repository, ya website files available nahi mile; is chat mein koi dedicated debate command exposed nahi hua.

**Not verified:** kis company ki exact website hai; website ka actual URL; original repo; running admin dashboard; present content, code, designs, analytics, ya campaign results; original project prompt path; external ChatGPT debate ka execution.

**Result:** abhi website ka real audit, actual two-model debate, design approval, implementation, ya deployment **complete nahi** hua. Yeh files ek high-quality execution brief aur collaboration protocol hain, na ki kiye gaye implementation ka evidence.

## Review karte waqt kya decide karna hai?

Owner review ka focus brand identity direction, motion intensity, target buyer journey, content claims, contact data fields, admin priorities aur approval boundaries par hona chahiye. Inmein koi bhi requirement change ho, to versioned update aur change log maintain karna chahiye. Jab actual project repository accessible ho, prompt pehle usse inspect karega, phir context-specific decisions deliver karega.
